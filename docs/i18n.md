# Translating the UI (English and Spanish)

The trainer shows its UI in English (the default) or Spanish (Settings → Overlay → Language, applied at once). English is the source language: the English text in the code is the key of every translation, so an untranslated string simply stays English and English output never changes.

- Code: `aim_core::i18n` (language, catalog, pure lookups) and `aim_app::i18n` (the current language and the `tr*` helpers the UI calls).
- Catalogs: `locales/es/<area>.toml`, one file per area.
- Decision record: D18 in [`decisions.md`](decisions.md).

## How to translate an area

1. **Wrap the literal** where it is shown:

   | Text | Before | After |
   |---|---|---|
   | Fixed label | `ui.label("Reset")` | `ui.label(tr("Reset"))` |
   | Label table (`'static`) | `tab_bar(ui, &mut t, &TABS)` | `tab_bar(ui, &mut t, &labels(&TABS))` |
   | `&'static str` APIs (`rows.section`) | `rows.section(ui, "Overlay")` | `rows.section(ui, tr("Overlay"))` |
   | Values in order | `format!("{} hits", n)` | `tr_fmt("{} hits", &[&n])` |
   | Values by name | `format!("{n} of {total}")` | `tr_named("{n} of {total}", &[("n", &n), ("total", &total)])` |
   | Runtime text (content names) | `ui.label(&def.name)` | `ui.label(tr(&def.name))` |

   `use crate::i18n::{tr, tr_fmt, tr_named, labels};` in `aim_app`. `tr` returns a `&'static str` for a `&'static str` key, so `'static` tables and APIs keep working.
2. **Add the entries** to your area's catalog file, keyed by the exact English text (same spaces, punctuation and symbols):

   ```toml
   "Reset" = "Restablecer"
   "{} hits" = "{} aciertos"
   "{n} of {total}" = "{n} de {total}"
   ```

3. **Run `cargo test --workspace`.** The English tests must pass unchanged, and the catalog check must report nothing.

### Placeholders

- `{}` is filled in order; `{name}` is filled by name. Use named placeholders when Spanish needs a different word order.
- A translation must keep exactly the same placeholders as its key (the same number of `{}` and the same names). The catalog check fails otherwise.
- Format specs are not supported (`{:.1}`, `{:>5}`). Format the value first and pass the string: `tr_fmt("{}% accuracy", &[&format!("{:.1}", acc)])`. The English output is then identical to the old `format!`.
- `{{` and `}}` are literal braces, as in `format!`.

### Plurals and grammar

There is no plural engine. Pick one of these, in this order:

1. Write the sentence so one form fits both numbers: `"Targets: {}"` instead of `"{} targets"`.
2. Use two keys and choose in code: `if n == 1 { tr("1 target left") } else { tr_fmt("{} targets left", &[&n]) }`. Both keys need entries.

Do not build sentences from translated fragments (`tr("You hit") + " " + tr("3 targets")`): word order differs between languages. Translate the whole sentence as one template.

### One English text, one translation

Because the English text is the key, the same English string has one Spanish translation everywhere. Two areas may both list it only with the same translation; a different one fails the catalog check. If a word really needs two translations (for example "Play" as a button and as a noun), change the English source text to something more specific in the same change, and update the English tests that pin it.

## What stays English

- **AI coach and MCP:** the player context, digests, prompts, tool results and anything sent to a model or over MCP use the English source text. Never call `tr` in `aim_core::coach`, `aim_ai` or `aim_mcp`, or on text that is built for them.
- **Files:** settings, history CSV, replays, journal, proof codes, content TOML and exported files keep their English (or code) values. Translate only when displaying.
- **Logs** (`bevy::log`, `eprintln!`) and command-line output.
- **Identifiers:** scenario, routine and benchmark ids, keys, units such as `cm/360`, `eDPI`, `DPI`.
- **Language names** in the selector ("English", "Español") are always written in their own language.

## Tests

- Never call `set_language` in a test. Tests run in parallel in one process, and hundreds of them assert English text. Use the pure functions: `aim_core::i18n::tr_in(Lang::Es, "...")`, `tr_fmt_in`, `tr_named_in`, and `aim_app::i18n::labels_in`.
- Existing English assertions must stay green unchanged; add a Spanish assertion through the `*_in` functions where it proves something (see the tab-label test in `pages/menu.rs`).
- `aim_core::i18n::check(ES_SOURCES)` must return no issues (`the_spanish_catalog_files_are_consistent`). It reports:
  - a file that is not a flat TOML table of strings;
  - an empty translation;
  - a translation whose placeholders differ from its key;
  - one English key with different translations in two areas.
- The font test (`ui/atoms/fonts.rs`) checks that the UI font draws á é í ó ú ñ ¿ ¡ ü and their capitals.

## Areas and catalog files

Each area owns one file, so translators working on different areas never edit the same file. Every file is already listed in `aim_core::i18n::ES_SOURCES`; add a new area only with a new file and a line there.

| Area | Catalog | What it covers |
|---|---|---|
| menu | `locales/es/menu.toml` | Main menu chrome and tab labels (`pages/menu.rs`), Today tab (`today_panel`), first-run wizard, scenario browser, routine and arena lists, benchmark panel |
| settings | `locales/es/settings.toml` | Settings page and its panels (`settings_panels`, `feedback_settings`, `hotkey_settings`, `restart_key_setting`, `dpi_check`, `profile_code`), break banner and breaks page |
| results | `locales/es/results.toml` | Results page and cards (`pages/results.rs`, `results_card`, `results_visuals`, `analysis_panel`, `potential_tip`, `proof_panel`) |
| replays | `locales/es/replays.toml` | Replay viewer, replay comparison, mistake player |
| coach | `locales/es/coach.toml` | Coach tab UI only (`coach_panel`). The text sent to models stays English |
| hud | `locales/es/hud.toml` | In-run HUD and overlays (`pages/hud.rs`, `hud_panels`, kill feed, health bar, death screen and recap, coaching overlay, decision, pace, perception, priority, moving and audio-cue panels) |
| progress | `locales/es/progress.toml` | Progress tab (`progress_panel`, `history_chart`, `journal_panel`, `flick_directions`) |
| tools | `locales/es/tools.toml` | Tools tab (`sens_converter`, `sens_finder`, `sens_suggestion`, `system_check`) |
| content | `locales/es/content.toml` | Scenario, routine, benchmark and arena names, descriptions and notes from `content/`, keyed by their English text and translated at display time (`tr(&def.name)`). The TOML files stay English |
| rules | `locales/es/rules.toml` | Rule meanings and tips shown for scenarios and arenas |
| core | `locales/es/core.toml` | Sentences built in `aim_core` (mistake tips, findings, metric labels, death recap text) |

If a component is not in the table, use the area of the page that shows it. Shared words (`"Cancel"`, `"Back"`) can appear in several files as long as the translation is identical.

### Core sentences

`aim_core` never reads the current language: it has no globals. To localize a sentence built in the core, either have the app translate it at display time (when the core returns fixed English text or exposes the template and its values), or give the builder an explicit `Lang` parameter and call `tr_fmt_in(lang, ...)`. Keep the English output byte-identical, and keep the English version for anything the coach or MCP receives.
